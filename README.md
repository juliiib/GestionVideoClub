# GestionVideoClub

A REST API for managing a video rental store (clients, employees, movies, copies, rentals and fines), built with **ASP.NET Core** and **.NET 10**, following **Clean Architecture** principles.

> **Academic project.** This system was built as a coursework project for university, as a hands-on exercise in applying software architecture and backend best practices to a realistic domain. It is not a production service, but it is designed and coded as if it were one.

## Overview

A video club needs to track its movie catalog, the physical/digital copies available in different formats, who rents what and when, and the fines generated by late or damaged returns. This API models that domain end-to-end: authentication and role-based access for employees and clients, a movie catalog enriched with data from a public external API, copy and format management, the full rental lifecycle, and fine generation and payment.

## Tech Stack

- **.NET 10 / ASP.NET Core Web API** — HTTP layer, controllers, hosting
- **Entity Framework Core 10 (SQL Server provider)** — persistence and migrations
- **JWT Bearer Authentication** — stateless auth with role-based policies (`Employee`, `Client`)
- **BCrypt.Net** — password hashing
- **Swagger / Swashbuckle** — interactive API documentation with bearer-token support
- **OMDb API** — external integration to auto-complete movie metadata (genre, duration, year, plot, poster) from just a title
- **.NET User Secrets** — local secret management (DB connection, JWT key, OMDb API key) kept out of source control

## Architecture

The solution is split into four projects, enforcing a strict dependency direction (outer layers depend on inner ones, never the reverse):

```
GestionVideoClub.Domain          → Entities, domain enums, domain interfaces (no dependencies)
GestionVideoClub.Application     → Use cases / services, DTOs, application interfaces (depends on Domain)
GestionVideoClub.Infrastructure  → EF Core DbContext, repositories, JWT/BCrypt/OMDb implementations (depends on Domain)
GestionVideoClub (Presentation)  → Controllers, DI wiring, auth middleware (depends on all of the above)
```

**Domain** entities are self-validating and expose no public setters — all state changes go through constructors or explicit behavior methods (e.g. `Rent.Return()`, `Fine.PayFine()`), keeping business invariants inside the entity itself rather than scattered across services.

**Application** services orchestrate use cases: they combine repository calls, enforce business rules that span multiple entities, and talk to Domain-level abstractions (like `IMovieInfoService`) without knowing which concrete technology implements them.

**Infrastructure** provides the concrete implementations Application depends on — EF Core repositories, the OMDb HTTP client, JWT token generation and BCrypt hashing — so swapping any of these (e.g. a different database or a different movie-info provider) would not require touching business logic.

**Presentation** wires everything together via dependency injection, exposes the HTTP surface, and applies cross-cutting concerns such as authentication/authorization policies and Swagger documentation.

This separation keeps business rules independent of frameworks and infrastructure, and the domain is unit-testable in isolation.

## Key Features

- **JWT authentication with role-based policies** — `Employee` and `Client` roles map to distinct authorization policies (`EmployeesOnly`, `EmployeesAndClients`) enforced per endpoint.
- **External API integration (OMDb)** — when an employee registers a new movie, only the title (and optionally the release year, to disambiguate) plus the age classification need to be entered manually; genre, duration, year and plot are fetched automatically.
- **Full rental lifecycle** — rent a copy, track expected vs. actual return dates, and automatically reflect copy availability.
- **Fine management** — fines tied to a rental for late returns, damaged items, or lost items, with payment tracking.
- **Database seeding** — a seed routine populates a development database with consistent sample data (including hashed passwords) on startup.
- **Self-documenting API** — Swagger UI with a configured bearer-token security scheme for exploring and testing authenticated endpoints directly from the browser.

## Domain Model

| Entity | Responsibility |
|---|---|
| `Person` (abstract) → `Client`, `Employee` | Shared identity/contact data; employees additionally track shift and salary |
| `Movie` | Catalog metadata, partly populated from OMDb |
| `Format` | Playback format (e.g. DVD, Blu-ray) with image quality and additional cost |
| `Copy` | A rentable unit of a movie in a given format, with state (`healthy`/`damaged`) and availability |
| `Rent` | Links a `Copy`, `Client` and `Employee`; tracks dates and state (`Active`/`Returned`/`Overdue`) |
| `Fine` | Generated from a `Rent`; tracks motive, amount and payment state |

## Project Structure

```
GestionVideoClub.Domain/
  Entities/        Core business entities
  Interfaces/       Repository & service contracts owned by the domain
  Models/           Domain-level data not persisted (e.g. OMDb result)

GestionVideoClub.Application/
  DTOs/             Request/response contracts for the API
  Interfaces/        Application service contracts
  Services/          Use-case orchestration

GestionVideoClub.Infrastructure/
  Persistence/       DbContext, EF configurations, seeder
  Repositories/       EF Core repository implementations
  ExternalServices/   JWT, BCrypt, OMDb client implementations

GestionVideoClub/ (Presentation)
  Controllers/        API endpoints
  Program.cs           DI composition, middleware pipeline
  Policies.cs          Authorization policy names

docs/                 Design notes on auth, persistence, external API integration, seeding and DTOs/error handling
```

The [docs/](docs/) folder contains deeper write-ups of specific design decisions (authentication flow, persistence choices, the OMDb integration, the seeder, and the DTO/error-handling conventions used across controllers).

## Running Locally

**Prerequisites:** .NET 10 SDK, SQL Server (local or containerized), an [OMDb API key](https://www.omdbapi.com/apikey.aspx) (free tier).

```bash
# Configure secrets (never committed to source control)
dotnet user-secrets set "ConnectionStrings:GestionVideoClubDb" "<your-connection-string>" --project GestionVideoClub
dotnet user-secrets set "Jwt:Key" "<a-long-random-secret>" --project GestionVideoClub
dotnet user-secrets set "Omdb:ApiKey" "<your-omdb-api-key>" --project GestionVideoClub

# Run (applies pending migrations and seeds sample data automatically in Development)
dotnet run --project GestionVideoClub
```

Swagger UI is available at `/swagger` when running in the `Development` environment.
